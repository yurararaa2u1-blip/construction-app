# 建築工事工程管理システム

> 建築工事現場の「進捗管理」と「遅延通知」をブラウザとメールでできるWebアプリ

**デモ環境**：現在停止中（詳細は「既知の課題」を参照）

---

## 📖 このプロジェクトについて

現場管理の課題（進捗の属人化・遅延発見の遅れ・情報共有の非効率）を解決するため、**役割ベース（admin / supervisor / viewer）** で機能が分かれる工程管理システムを構築しました。

- 🔒 JWT認証、bcryptでパスワードハッシュ化
- 📊 現場・工程のCRUD、進捗率のリアルタイム更新
- 📅 バッチで遅延自動判定、AWS SES経由でメール通知
- ☁️ AWS EC2/RDS/S3/CloudFront/SES で構築（デモ環境は現在停止中）
- 📱 スマホ・PC対応（レスポンシブ）

## 💡 工夫した点

### 要件定義から順に進めた

「作りたいものを思いついてコードを書き始める」のではなく、要件定義 → 設計 → 実装 → テストの順で進めました。実装前に以下の設計書を作成しています。

- アーキテクチャ設計書 / データベース設計書 / API設計書 / 画面設計書

建築業界での施工管理の経験上、図面と工程表を固めずに着工すると手戻りが発生することを繰り返し見てきました。開発でも同じだと考え、先に設計を固める進め方を選んでいます。

### テスト計画を立てて実施し、結果を文書化した

行き当たりばったりに動作確認するのではなく、テスト計画書を作成した上で実施し、結果を記録として残しました（[テスト計画書と結果](docs/test-plan.html)）。

### 変更履歴を既存の標準規約に沿わせた

変更履歴は独自の書式を作らず、[Keep a Changelog](https://keepachangelog.com/ja/1.1.0/) の形式に準拠させました。変更内容を「追加 / 修正 / 削除」などに分類し、コミットログの羅列ではなく人が読んで分かる粒度で記述しています。自分だけが読むものではないため、広く使われている規約に合わせる方が読み手の負担が小さいと考えました。

### 秘匿情報の管理

公開にあたり、以下を実施しました。

- `.env` 系ファイル、SSH秘密鍵、ローカル開発用のシードデータを Git 管理から除外
- 全27コミットの履歴を遡り、アクセスキー・DBパスワード・秘密鍵の埋め込みが無いことを確認
- 追跡対象外だがローカルに残存するファイルについても棚卸しを実施

3点目は、履歴の調査を終えた後に気づいた点です。Git 履歴が綺麗であることと、配布物が安全であることは別問題でした。実際、履歴には含まれないものの、ローカルに EC2 接続用の秘密鍵が残っていました。

## ⚠️ 既知の課題

### 権限昇格の脆弱性（対応予定）

ユーザー登録エンドポイントで、リクエストボディから `role` をそのまま受け取る実装になっています。このため、リクエストを直接送信すれば `admin` 権限を自己付与できる状態です。

自分で書いたコードを読み直す過程で発見しました。現在修正に取り組んでおり、完了後に発見から修正までの経緯をここに記載する予定です。

### 自動テストが無い

テストは手動で実施しており、自動テストは実装していません。このため、機能追加や修正のたびに全項目を再確認することが現実的でなく、変更時の影響範囲の検証が十分とは言えません。

### デモ環境を停止中

AWS の利用費用を抑えるため、現在デモ環境を停止しています。上記の脆弱性を修正した上で、再公開する予定です。

## 🚀 ローカル起動方法

### 前提

- Node.js v20 以上
- PostgreSQL 15 以上
- ローカルにPostgreSQLインスタンス（もしくは `.env` で外部DBを指定）

### バックエンド

```bash
cd backend
npm install
# .env ファイルを作成（DB接続情報、JWT_SECRET等を記述）
node src/app.js
# → http://localhost:3000 で起動
```

### フロントエンド

```bash
cd frontend
npm install
npm start
# → http://localhost:3001 で起動（ブラウザが自動オープン）
```
